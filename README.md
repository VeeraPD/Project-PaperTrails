# Papertrail

A PDF research assistant built with FastAPI, PyMuPDF, Gemini, ChromaDB, and plain HTML/CSS/JavaScript.

## How it works

PDF upload → per-page text extraction → paragraph-aware chunks → Gemini embeddings → ChromaDB collection → semantic retrieval → Gemini answer with page citations. Each browser gets a random workspace cookie; its document manifest and passages live in Chroma. Locally Chroma uses a persistent directory; on Vercel it connects to Chroma Cloud. Chat turns stay in browser memory and are sent with each question. Original PDFs are not retained; citations identify files and pages, but cannot open the originals.

ChromaDB stores Gemini's externally generated 768-dimensional vectors and PDF/page metadata in one collection, partitioned by browser workspace ID. Local development uses `chromadb.PersistentClient` in `./chroma_data`. Vercel uses `chromadb.CloudClient` because serverless local files do not persist. Chroma is the sole vector store; Gemini handles the embeddings and answers. The manifest is a record in the collection. Reset deletes the current workspace's records. Do not reuse a collection with embeddings generated by another model; create a new Chroma database or collection and reupload the PDFs.

## Requirements and environment

Python 3.11+, Gemini API key with embedding and text generation access, Chroma Cloud credentials for deployment. Copy `.env.example` to `.env`, fill in `GEMINI_API_KEY`; for local use, Chroma runs with no Chroma account. `GEMINI_CHAT_MODEL` is optional and defaults to `gemini-3.8-flash`.

## Run locally

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env               # Windows: copy .env.example .env
uvicorn app:app --reload
```

Open http://localhost:8000. Upload a text-based PDF and ask a question. Costs accrue on Gemini and, when deployed, Chroma Cloud accounts.

## GitHub and Vercel

```bash
git init
git add .
git commit -m "Build Papertrail PDF assistant"
git branch -M main
git remote add origin https://github.com/YOUR_USER/YOUR_REPO.git
git push -u origin main
```

Create an empty GitHub repository first. Import that repository in Vercel; root directory is the project root (`pdf-rag-chatbot` if committed inside a parent repository). Create a Chroma Cloud database. Add `GEMINI_API_KEY`, `CHROMA_API_KEY`, `CHROMA_TENANT`, `CHROMA_DATABASE`, and optionally `GEMINI_CHAT_MODEL` under project environment variables. Chroma Cloud is required on Vercel; `CHROMA_PATH` is only for local development. Deploy. Vercel uses `vercel.json` to run FastAPI in a Python function; the static UI is served by that app. Do not add `.env` to Git.

## Verify

1. Upload two small PDFs and confirm both appear with readable page counts.
2. Ask a question answered on a known page; check the answer and that its citation names that PDF and page.
3. Ask a follow-up using “that” or “it”; check that new claims cite uploaded pages.
4. Ask about something absent; expect an explicit inability to answer.
5. Reload and confirm the document list remains; clear workspace and check that the list disappears.
6. Try an invalid file, a protected PDF, and a scanned PDF to see actionable errors.

## Limits

Upload up to five PDFs per request; the combined request is limited to 4 MB, and each PDF to 400 pages and 300 passages. Vercel functions have a 4.5 MB request-body cap; 4 MB leaves room for multipart overhead. Large ingestion jobs can exceed the configured 60-second function duration; reduce document size or add a background worker/direct upload architecture later. This MVP does not OCR scanned documents, store chat history across reloads, store original PDFs, offer user accounts, or provide robust abuse prevention. Random cookies provide workspace separation, not authentication: deploy behind access control for sensitive PDFs or public traffic. Do not upload documents your Gemini/Chroma data policies prohibit. Concurrent uploads to the same workspace may race when updating the document manifest; upload sequentially. Stored workspaces persist until cleared (or removed by your database retention settings); users who clear browser cookies lose access to their previous workspace. Review service quotas and add auth, rate limits, retention, and async ingestion before opening this to the public.
